= zed-http-client
:toc: macro
:toclevels: 2
:source-highlighter: highlight.js
:project-version: 0.4.6

A Zed editor extension and companion Rust CLI for running IntelliJ-style HTTP and GraphQL request files inside Zed or from the terminal.

WARNING: This project aims for practical compatibility with the JetBrains HTTP Client file format but is not affiliated with JetBrains.

== Quick start

Install the CLI in one of three ways:

* *Prebuilt binary* (no Rust toolchain needed): download the archive for your platform from the link:{project-repo}/releases[GitHub Releases page] — `linux-x86_64`, `linux-aarch64`, `macos-x86_64`, `macos-aarch64`, or `windows-x86_64`. Extract and put `zed-http` on your `PATH`.
* *From source*: `cargo install --path crates/zed-http-cli` (lands in `~/.cargo/bin/`).
* *In-tree*: the project-local `.zed/tasks.json` invokes `cargo run -p zed-http-cli` so no install is needed if you only use it from Zed.

Build the CLI directly:

[source,bash]
----
cargo build -p zed-http-cli
----

Run the bundled example against the included envs:

[source,bash]
----
cargo run -p zed-http-cli -- run --file examples/requests.http --name "Health check" --env dev
----

List requests and available environments:

[source,bash]
----
cargo run -p zed-http-cli -- list --file examples/requests.http
cargo run -p zed-http-cli -- envs --file examples/requests.http
----

Validate without sending:

[source,bash]
----
cargo run -p zed-http-cli -- check --file examples/requests.http --env dev
----

== Commands at a glance

[source,bash]
----
zed-http run --file requests.http [--line N | --name "Title"] [--env <name>] [--var k=v]
zed-http run-all --file requests.http [--env <name>] [--bail] [--var k=v] [--output json]
zed-http check --file requests.http [--env <name>]
zed-http list --file requests.http
zed-http envs --file requests.http
zed-http format --file requests.http [--in-place | --check]
zed-http introspect --file requests.http --name "<GRAPHQL request>" [--env <name>]
zed-http schema list
zed-http schema show --host <host>
zed-http import postman --file collection.json [--out requests.http]
zed-http import curl 'curl -H "Authorization: Bearer ..." https://api.example.com/users'
zed-http import har --file recording.har [--out requests.http] [--name-prefix "Smoke"]
zed-http completions {bash|zsh|fish|powershell|elvish}
----

See the link:src/docs/modules/ROOT/pages/cli-reference.adoc[CLI reference] for the full flag list, including `--no-validate`, `--no-cookies`, `--cookie-jar`, and `--worktree`.

== Feature highlights

* IntelliJ HTTP Client format: `.http` and `.rest` files with `###`-separated request blocks, headers, JSON bodies, body-from-file (`< ./payload.json`), and response redirects (`>>` / `>>!`).
* `http-client.env.json` and `http-client.private.env.json` discovery with public-then-private layering plus in-file `@var = value` overlays. File-level `# @env <name>` directive selects a default when `--env` is not passed.
* GraphQL: `GRAPHQL` pseudo-method with operation, variables, and operation-name detection. Schema introspection (`zed-http introspect`) caches schemas at `<base>/.zed-http/schema/<host>.json` for schema-aware field validation. `# @fragments ./path.graphql` includes fragments from sibling files.
* Validation: `zed-http check` and pre-flight validation in `zed-http run` flag missing or extra GraphQL variables, and unknown top-level fields when a schema is cached.
* Response assertions: `# @expect-status`, `# @expect-header`, `# @expect-json` directives evaluated after the response with `<file>:<line>: <message>` diagnostics and non-zero exit on failure.
* Persistent cookie jar at `<base>/.zed-http/cookies.json`, including session cookies so multi-step login → action flows survive across invocations.
* Per-request options: `# @timeout`, `# @connection-timeout`, `# @no-redirect`, `# @fragments`.
* Dynamic variables: `{{$uuid}}` (v7), `{{$timestamp}}`, `{{$isoTimestamp}}`, `{{$randomInt}}` — generated per request, consistent within a request, shadowable by user vars.
* `zed-http run-all` executes every request in a file with a pass/fail summary, shared cookie jar, and `--bail` / `--output json` modes for CI.
* Response variable capture: `# @capture <name> json:<pointer>` / `header:<name>` / `status` lifts a value out of the response into a variable that later requests in the same `run-all` reference as `{{name}}` — login → action workflows without a JS runtime.
* `--var name=value` CLI flag (repeatable) overrides any variable from outside, e.g. `--var apiKey=$(security find-generic-password ...)`.
* Canonical `zed-http format` round-trip, plus a `--check` mode for CI.
* Postman v2.1 collection import via `zed-http import postman`.
* curl import via `zed-http import curl` (positional, `--file`, or `--stdin`) — paste the "Copy as cURL" shape from browser devtools and get a canonical `.http` block back.
* HAR import via `zed-http import har` — translate a browser devtools "Save all as HAR with content" export into a multi-request `.http` file in one go.
* Shell completions via `zed-http completions <shell>` (bash / zsh / fish / powershell / elvish), generated by `clap_complete` so subcommand and flag completion stay current automatically.
* Zed integration: Tree-sitter syntax highlighting, runnable detection, snippets, and a pre-wired `.zed/tasks.json` covering per-environment runners.

== Zed integration in one paragraph

Open the project in Zed, run `zed: install dev extension` from the command palette and point it at this repo. The bundled `.zed/tasks.json` wires four per-environment runnables against the `http-client-request` tag on every request line, plus three ancillary tasks (`list requests`, `list available environments`, `validate file`). With your cursor on a request, run `task: spawn` → pick the environment → output appears in Zed's terminal, with the response body also saved under `examples/.zed-http/responses/` for later inspection. The link:src/docs/modules/ROOT/pages/zed-integration.adoc[Zed integration page] covers the suffix-conflict caveats and how to add a new environment to the task list.

== Status and deferred work

Version {project-version}. PRD-aligned roadmap tiers v0.1 through v0.4 (first slice) are complete. See link:CHANGELOG.md[CHANGELOG.md] for the per-release notes and link:src/docs/modules/ROOT/pages/roadmap.adoc[roadmap] for what is still deferred. The headline gaps:

* Multipart / form-data request bodies.
* JS pre-request scripts and response handlers (would need an embedded JS runtime).
* OAuth flows and client certificate config.
* A custom Zed output panel — the task terminal is the practical surface today.
* Inline-fragment GraphQL validation (current validator skips fragments since type-condition resolution is not yet implemented).
